# Открытые вопросы к запуску

Для теста всё решено (раздел 8 ТЗ). Ниже пункты, которые закрываются к боевому запуску. В коде они уже заложены параметрами: достаточно поправить `.env` и выполнить `docker compose up -d`, пересборка не нужна.

| Вопрос | Текущий дефолт (тест) | Что меняется |
| --- | --- | --- |
| Таблица клиента: новая или существующая, точные заголовки колонок | Тестовая таблица из `docs/test-sheet.csv`, лист «Заявки», заголовки в строке 1 по разделу 5.1 ТЗ | `SHEETS_SPREADSHEET_ID`, `SHEETS_SHEET_NAME`, `SHEETS_HEADER_ROW`, `SHEETS_COL_*` (текст заголовка для каждого поля). Сервисному аккаунту выдать «Редактор» на таблицу клиента |
| Боевой сервер | Временный сервер разработчика | Перенос на KZ VPS клиента (2 vCPU / 4 ГБ / 40–50 ГБ) по README. Сессию WhatsApp можно перенести бэкапом volume `wa-session` или заново отсканировать QR |
| Работать ли в выходные | Нет (`false`), окно 08:00–20:00 по Алматы | `DISPATCH_WEEKENDS_ENABLED`, `DISPATCH_WINDOW_START`, `DISPATCH_WINDOW_END` |
| Клиентский чат для алертов | Заказчик ТЗ и разработчик | Добавить chat_id клиента в `TELEGRAM_CHAT_IDS` через запятую |
| Подтверждение схемы прогрева | 45 → 80 → 120 → 170 → 220, с 6-го дня весь список активных групп | `WARMUP_DAILY_LIMITS`, `WARMUP_ENABLED` |
| Контакт в сообщении | Задаётся при настройке теста | `MESSAGE_CONTACT` |

## Решения, принятые по умолчанию, где ТЗ не уточняет

| Тема | Решение | Где меняется |
| --- | --- | --- |
| Данные заявки «Калжат → Баку» | В ТЗ нет её полного текста. В `docs/test-sheet.csv` заполнена правдоподобными значениями по образцу, эталон `golden/kalzhat-baku.txt` построен по ним. При получении реального текста заменить строку CSV и эталон | `docs/test-sheet.csv`, `src/test/resources/golden/kalzhat-baku.txt` |
| Нумерация при `MESSAGE_NUMBERING=true` | Keycap-цифры числового ID перед первой строкой: `1️⃣7️⃣ 📍*…*`. Для нечислового ID нумерация не ставится | `MESSAGE_NUMBERING` |
| Формат ID | Следующее число после максимального ID в таблице и БД | — |
| Волны и паузы | Волна 25 групп, между волнами 10–20 мин, между группами 20–60 с, «печатает» 2–6 с | `DISPATCH_*` |
| Пороги риска | Окно 1 ч, 5 сигналов → паузы ×2 и алерт, 10 сигналов → остановка и алерт | `RISK_*` |
| Что считается в суточный лимит | Каждая попытка отправки (успешная и неуспешная) | — |
| Частичная неудача | Если хотя бы одна группа получила заявку — «Отправлено», счётчик показывает реальные `отправлено / всего`. Если ни одна — «Ошибка: не отправлено ни в одну группу» | — |
| Обрыв посреди отправки | Доставка в статусе SENDING после рестарта считается отправленной (дубль хуже пропуска), в логе строка `RECOVERED_AS_SENT` | — |
| Watchdog | 8 попыток переподключения, задержка 10 с × 2^n до 15 мин; после исчерпания — алерт и попытки раз в 15 мин | `WATCHDOG_*` |
