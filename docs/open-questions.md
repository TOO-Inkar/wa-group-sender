# Открытые вопросы (раздел 8 ТЗ) и принятые дефолты

Ни один вопрос не блокирует запуск: везде взят разумный дефолт, всё меняется через `.env` без пересборки (после правки `.env` — `docker compose up -d`).

| # | Вопрос | Принятый дефолт | Где меняется |
| --- | --- | --- | --- |
| 1 | Образец фирменного формата сообщения | Пример в `templates/message.txt`: эмодзи-заголовок с ID, маршрут, тоннаж, груз, дата, фрахт, призыв писать в личку. Плейсхолдеры `{{id}} {{route}} {{tonnage}} {{cargo}} {{date}} {{freight}}` (есть русские синонимы `{{маршрут}}` и т.д.) | `templates/message.txt` на хосте, подхватывается при каждой новой заявке без рестарта. Путь: `TEMPLATE_PATH` |
| 2 | Новая таблица или существующая, точные колонки и форматы | Новая таблица, лист «Заявки», строка 1 — заголовки, данные со строки 2. Колонки A–I: ID, Маршрут, Тоннаж, Груз, Дата, Фрахт, Статус, Отправлено / всего, Завершено. Значения берутся как отформатированный текст ячейки, без парсинга | `SHEETS_SHEET_NAME`, `SHEETS_FIRST_DATA_ROW`, `SHEETS_COL_*` (буква колонки для каждого поля) |
| 3 | Рабочее окно, выходные | 08:00–21:00 по Алматы, выходные включены. Окно через полночь тоже поддерживается (например 22:00–06:00), `start = end` — круглосуточно | `DISPATCH_WINDOW_START`, `DISPATCH_WINDOW_END`, `DISPATCH_WEEKENDS_ENABLED` |
| 4 | Кто получает алерты и в какой Telegram-чат | Один чат администратора в Telegram. Email выключен | `NOTIFY_CHANNEL` (`telegram`, `email` или `telegram,email`), `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `NOTIFY_EMAIL_*`, `SPRING_MAIL_*`. Повтор одного и того же алерта не чаще `NOTIFY_COOLDOWN` (15 мин) |
| 5 | Схема прогрева | 4 дня: 50 → 100 → 150 → 250 отправок в группы в сутки, с 5-го дня без лимита. День прогрева считается от даты первой отправки (календарные дни по Алматы). Остаток переносится на следующие сутки с того же места | `WARMUP_DAILY_LIMITS` (список через запятую), `WARMUP_ENABLED` |
| 6 | Повторять ли заявку в группах через N часов | Нет, только одна отправка на заявку. Повтор можно сделать вручную: новая строка с тем же текстом (новый ID) | — (функция не реализована, при необходимости — отдельная доработка) |
| 7 | Кто заказывает VPS и даёт SSH-доступ | Заказчик заказывает VPS (PS.kz / Hoster.kz, Ubuntu 24.04, 2 vCPU / 4 ГБ / 40 ГБ) и даёт SSH-доступ. Разворачивание по README | — |

## Дополнительные решения, не описанные в ТЗ

| Тема | Решение | Где меняется |
| --- | --- | --- |
| Размер волны и паузы | Волна 25 групп, пауза между волнами 10–20 мин, между группами 20–60 с, «печатает» 2–6 с | `DISPATCH_WAVE_SIZE`, `DISPATCH_WAVE_PAUSE_MIN/MAX`, `DISPATCH_GROUP_PAUSE_MIN/MAX`, `DISPATCH_TYPING_MIN/MAX` |
| Пороги риска | Окно 1 ч; 5 сигналов — паузы ×2 и алерт; 10 сигналов — остановка и алерт. Сигналы: удаление из группы, ошибка отправки, разрыв сессии, разлогин, бан | `RISK_WINDOW`, `RISK_WARN_THRESHOLD`, `RISK_CRITICAL_THRESHOLD`, `RISK_PAUSE_MULTIPLIER` |
| Что считается в суточный лимит | Каждая попытка отправки (успешная и неуспешная): для антибана важна активность, а не результат | — |
| Частичная неудача | Если хотя бы одна группа получила заявку — статус «Отправлено», счётчик показывает реальное `отправлено/всего`. Если ни одна — «Ошибка: не отправлено ни в одну группу» | — |
| Обрыв посреди отправки | Доставка в статусе SENDING после рестарта считается отправленной (дубль хуже пропуска), в логе строка `RECOVERED_AS_SENT` | — |
| Дубликат строки с тем же ID | Статус «Ошибка: дубликат ID …», повторной отправки нет | — |
| Формат ID | `RYYMMDD-XXXXX`, генерируется, если ячейка ID пуста | — |
| Watchdog | 8 попыток переподключения, задержка 10 с × 2^n до 15 мин; после исчерпания — алерт и попытки раз в 15 мин | `WATCHDOG_*` |
| Прогресс в таблицу | Пакетно: раз в 60 с, на границе волны и при смене статуса | `SHEETS_PROGRESS_FLUSH_INTERVAL` |
