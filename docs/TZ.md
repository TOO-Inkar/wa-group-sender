# ТЗ: WhatsApp-рассылка по группам

Sep 28, 2026 · @Meiirzhan Muratbekuly

## 1. Общие сведения

Нужен Java-сервис, который берёт новые заявки на грузоперевозки из Google Sheets и сам публикует их в \~250 WhatsApp-групп из папки «Архив» отдельного номера, с защитой от блокировки. Основание — КП «Автоматическая рассылка заявок по WhatsApp-группам» v1, бюджет настройки 200 000 ₸, срок 5–8 рабочих дней.

- **Проблема сейчас:** менеджер вручную рассылает каждую заявку по \~250 группам.
- **Способ:** неофициальный — эмуляция WhatsApp Web (без WhatsApp Business API и верификации Meta).
- **Номер:** отдельный тестовый номер заказчика. Основной бизнес-номер не подключать и не трогать.
- **Риск:** номер может быть заблокирован в любой момент. Задача разработчика — снизить вероятность, а не гарантировать её отсутствие.

**Входит в объём:** подключение по QR, сохранение сессии, чтение заявок из Sheets, получение списка групп, постинг с антибан-логикой, watchdog с уведомлениями, тест полного цикла.

**Не входит:** несколько номеров (отдельная опция), ежемесячная поддержка, восстановление после бана, официальный API.

| Роль | Что делает |
| --- | --- |

## 3. Функциональные требования

### 3.1. Подключение и сессия

1. При первом запуске сервис выводит QR-код (в лог как ASCII и как PNG-файл/эндпоинт) для привязки номера через «Связанные устройства».
2. Сессия (auth state) сохраняется на диск в volume и переживает перезапуск контейнера и сервера. Повторное сканирование QR не требуется, пока WhatsApp сам не разлогинит устройство.
3. При разлогине сервис переходит в режим ожидания QR и шлёт алерт администратору.

### 3.2. Чтение заявок из Google Sheets

1. Доступ через Google Sheets API и сервисный аккаунт; ID таблицы и имя листа — в конфиге.
2. Опрос таблицы по расписанию, интервал настраивается (по умолчанию 30 сек).
3. Новая заявка = строка с заполненными обязательными полями и пустым статусом. Строки с незаполненными полями пропускаются, в статус пишется «Ошибка: не заполнено <поле>».
4. Каждая заявка отправляется отдельным сообщением сразу после появления, без накопления.
5. Сервис пишет обратно в строку: статус (`В очереди`, `Отправляется`, `Отправлено`, `Ошибка`), счётчик `отправлено/всего групп`, время завершения.
6. Повторная отправка той же заявки исключена: идемпотентность по ID строки (или отдельной колонке ID).

### 3.3. Формат сообщения

1. Одна заявка = одно сообщение. Нумерация (1️⃣, 2️⃣) и разделитель `━━━━` из образца по умолчанию не выводятся; нумерацию можно включить флагом в конфиге. Контакт один на все заявки и хранится в конфиге.
2. Шаблон хранится во внешнем файле, меняется без пересборки. Разметка WhatsApp (`*жирный*`) и эмодзи передаются как есть, UTF-8.
3. Порядок блоков фиксированный. Пустые поля вместе со своей строкой не выводятся.

Шаблон по образцу заказчика:

```markdown
📍*{Маршрут}*

📅 *{Дата / срочность}*✅

🚛 {Машины и тоннаж — по строке на каждую конфигурацию}

📦 {Груз}
{Доп. условия — по строке, как ввёл менеджер}
💰 Фрахт {Фрахт}

📞 *{Контакт из конфига}*
```

Пример результата для строки «Хоргос → Баку»:

```markdown
📍*ХОРГОС → БАКУ*

📅 *Срочно, груз готов*✅

🚛 120 м³/5 осей — ⚖️ 21–22 т

📦 Хозтовары
🚗 Выход через Калжат
⛴️ По суше
⚡️ Скорость есть
💰 Фрахт 🔥🔥

📞 *{Контакт}*
```

### 3.4. Список групп

1. Целевые группы = все групповые чаты номера со статусом «в архиве». Разархивированные группы в рассылку не попадают.
2. Список синхронизируется при старте и затем периодически (например, раз в час); изменения пишутся в лог.
3. Группы, где номер больше не участник или не может писать (только админы), помечаются неактивными и исключаются.
4. Должна быть возможность выгрузить текущий список групп (лог или эндпоинт) для проверки на тесте.

### 3.5. Рассылка и антибан-логика

Все параметры ниже — в конфиге, без пересборки.

1. **Волны:** заявка делится на волны по N групп; между волнами пауза в заданном диапазоне.
2. **Случайные интервалы:** пауза между группами — случайное значение из диапазона, не фиксированное.
3. **Прогрев:** суточный лимит отправок в группы растёт по заданной схеме по дням. По умолчанию: старт 40–50 групп в сутки, выход на полный список за 5–7 дней. Что не влезло в лимит — переносится на следующие сутки.
4. **Ротация:** порядок групп перемешивается при каждой рассылке.
5. **Имитация активности:** перед отправкой в группу — статус «печатает» на случайное время.
6. **Рабочее окно:** рассылка только в заданные часы, по умолчанию с утра до вечера (08:00–20:00 по Алматы). Отправка в выходные — отдельный флаг в конфиге, значение уточняется. Вне окна заявки ждут в очереди.
7. **Мониторинг риска:** считать удаления из групп и ошибки отправки за скользящее окно. При превышении порога — автоматически увеличивать паузы (множитель), при критическом пороге — остановить рассылку и отправить алерт.
8. **Очередь:** если во время рассылки пришла новая заявка, она встаёт в очередь FIFO; параллельной отправки с одного номера нет.
9. Очередь и прогресс рассылки сохраняются: после перезапуска рассылка продолжается с места остановки, без повторов в уже отправленные группы.

Повторная отправка той же заявки в те же группы не делается: одна заявка — одна отправка в каждую группу.

### 3.6. Watchdog и уведомления

1. Автопереподключение при обрыве с экспоненциальной задержкой, N попыток.
2. Если восстановить не удалось, при разлогине, при сработке порога риска — алерт администратору.
3. Канал алертов — Telegram-бот; на тесте алерты получают заказчик ТЗ и разработчик, клиентский чат добавляется к запуску; токен и chat\_id в `.env`.
4. Healthcheck-эндпоинт: статус сессии, длина очереди, отправлено за сутки, текущий лимит прогрева.

Сигналы риска от watchdog возвращаются в диспетчер: он растягивает паузы или останавливает рассылку. Статус каждой заявки диспетчер пишет обратно в её строку таблицы.

### 4.1. Библиотека WhatsApp Web

Выбор библиотеки — первая задача (спайк, 1 день). Критерии: работает без браузера, поддерживает multi-device, отдаёт признак «в архиве» у чатов, умеет слать в группы и статус «печатает», живо поддерживается.

| Вариант | Как встраивается | Ресурсы | Замечание |
| --- | --- | --- | --- |
| Cobalt (Java) | Библиотека внутри сервиса | Лёгкий, без браузера | Приоритет: весь проект на Java. Проверить чтение архива |
| Baileys (Node.js) | Отдельный sidecar-контейнер с HTTP API, Java управляет | Лёгкий, без браузера | Запасной вариант, самое большое сообщество |
| whatsapp-web.js (Node.js) | Sidecar, внутри headless Chromium | Тяжёлый, 4 ГБ RAM | Только если первые два не подошли |

Результат спайка — короткий отчёт: выбранная библиотека, версия, подтверждение, что список архивных групп читается.

### 4.2. Google Sheets

- Google Sheets API v4, сервисный аккаунт с доступом «Редактор» к таблице.
- JSON-ключ сервисного аккаунта монтируется файлом, путь — в `.env`.

### 4.3. Уведомления

- Telegram Bot API: токен бота и список chat\_id получателей в `.env`.

## 5. Модель данных

### 5.1. Колонки Google Sheets

| Колонка | Кто заполняет | Обязательна | Пример |
| --- | --- | --- | --- |
| ID | Система (если пусто) | Да | 17 |
| Маршрут | Менеджер | Да | ХОРГОС → МОСКВА |
| Дата / срочность | Менеджер | Да | Погрузка 10 сентября |
| Машины и тоннаж | Менеджер | Да | 130 м³ / 6 осей — ⚖️ 23 т |
| Груз | Менеджер | Да | Хозтовары |
| Фрахт | Менеджер | Да | 🔥🔥 или сумма |
| Доп. условия | Менеджер | Нет | 🛃 Растаможка — Москва |
| Статус | Система | — | Отправлено |
| Отправлено / всего | Система | — | 248 / 250 |
| Завершено | Система | — | 2026-10-05 14:20 |

«Тоннаж» из базового списка объединён с машиной: в одной заявке бывает несколько конфигураций со своим тоннажем. «Машины и тоннаж» и «Доп. условия» — многострочные ячейки, одна строка ячейки = одна строка сообщения. Дата и фрахт — свободный текст, не типизированные поля.

На тест разработчик сам создаёт тестовую Google Таблицу с этими колонками. Таблицу клиента (новую или существующую) подключают после теста — сервис должен переключаться на неё сменой ID таблицы и маппинга колонок в конфиге.

### 5.2. Локальная БД

SQLite или H2 в volume — достаточно для одного номера. Таблицы:

- `request` — ID строки, текст сообщения, статус, время постановки и завершения.
- `wa_group` — JID группы, название, активна ли, дата последней синхронизации.
- `delivery` — заявка × группа: статус, время, текст ошибки. Уникальность по паре, чтобы не было повторов после рестарта.
- `risk_event` — тип сигнала (удаление, ошибка, разрыв), группа, время.
- `daily_counter` — дата, отправлено за сутки, лимит прогрева на эту дату.

## 7. Этапы и приёмка

Общий срок — 5–8 рабочих дней с момента, когда есть номер и доступ к таблице. Первые 50% оплаты заказчик вносит после успешного теста полного цикла (этап 5).

| Этап | Дни | Результат |
| --- | --- | --- |
| 1. Спайк библиотеки | 1 | Выбрана библиотека, подтверждено чтение архивных групп и отправка в группу |
| 2. Сессия, QR, watchdog | 1 | Сессия переживает рестарт, алерт в Telegram приходит |
| 3. Google Sheets | 1 | Тестовая таблица создана, новая строка попадает в очередь, статус пишется обратно |
| 4. Диспетчер и антибан | 1–2 | Волны, случайные паузы, прогрев, ротация, рабочее окно, реакция на сигналы риска |
| 5. Тест полного цикла | 1–2 | Заявка из таблицы доходит до тестовых групп без ошибок |
| 6. Деплой и передача | 1 | Тест — на временном сервере разработчика. Перенос на боевой VPS клиента и подключение его таблицы — после теста, сроки отдельно. README, `.env.example` |

### Критерии приёмки

- [ ] Сообщения для трёх заявок из образца (Калжат → Баку, Хоргос → Баку, Хоргос → Москва) собираются по шаблону и выглядят в WhatsApp как образец, включая жирный текст и эмодзи.

* [ ] После рестарта контейнера и VPS сервис поднимается без повторного QR.
* [ ] В рассылку попадают только группы «в архиве»; список выгружается и совпадает с телефоном.
* [ ] Новая строка в таблице уходит в группы без ручных действий; повторной отправки нет.
* [ ] Интервалы между группами случайные, порядок групп меняется от заявки к заявке (видно по логам).
* [ ] Суточный лимит прогрева соблюдается, остаток переносится на следующий день.
* [ ] Вне рабочего окна отправки нет.
* [ ] После обрыва и рестарта посреди рассылки уже отправленные группы не получают заявку повторно.
* [ ] При обрыве сессии или сработке порога риска приходит алерт в Telegram.
* [ ] Строка с незаполненным полем не отправляется, в статусе — понятная ошибка.
* [ ] Все параметры меняются через конфиг без пересборки.

### Что передаётся заказчику

Исходный код в репозитории, Docker-образ и `docker-compose.yml`, README по запуску, привязке QR и настройке лимитов, `.env.example`.
